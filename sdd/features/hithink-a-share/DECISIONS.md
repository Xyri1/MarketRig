# HiThink A-share data — Feature Decisions

Local decisions for Milestone R6, prefixed `HT-<n>`. They settle the product decisions taken on 2026-09-08 (recorded as D84) into mechanics. HiThink facts were verified the same day against the `main` branch of `HiThink-Tech/Financial-API` (MIT): the REST contract in `docs/api/` and `skills/hithink-finance/references/api/`, the hosted MCP contract in `docs/mcp.md`, the CLI and Python trees, and the exchange enumeration of the meta endpoints.

### HT-1 — One installation resource, one key, validated by one bounded request

**Decision:** HiThink is one installation resource, `hithink_provider`, with `state IN ('UNCONFIGURED','AVAILABLE','UNAVAILABLE')`, `validated_at_ns`, and a failure code and message. The base URL is compiled in (`https://fuyao.aicubes.cn`); `MARKETRIG_TEST_HITHINK_URL` is its only override, honored only beside `MARKETRIG_TEST_DATA_ROOT`. `PUT /research/hithink {api_key}` stores the key in the credential store under account `hithink_api_key`, validates it with exactly one bounded request — `GET /api/meta/tickers/search?q=600519&limit=1` — and answers the resource `AVAILABLE`, or `PROVIDER_REJECTED` without writing when the envelope's `code` is not `0` (the upstream `2003` on a bad key) and `PROVIDER_UNREACHABLE` on transport failure. `DELETE /research/hithink` removes the key and returns the row to `UNCONFIGURED`. Every answer carries `api_key_present` and never a key. Each change appends one installation event, `HITHINK_PROVIDER_CHANGED {state}`. The row also carries `a_share_feed` (`YAHOO | HITHINK`), the operator's choice of which client serves the `CN` catalog entries: a successful `PUT` sets it to `HITHINK`, `DELETE` forces `YAHOO`, and `PATCH /research/hithink {a_share_feed}` moves it while a key is present (`409 RESEARCH_UNCONFIGURED` otherwise). The toggle gates the feed alone; research is available whenever the key is. There is no per-desk key and no per-desk feed choice.

**Rationale:** The same shape as `memory_provider` (root §4.4), which the desktop and the credential store already handle. HiThink's own docs forbid probing with an unbounded full-market snapshot, and name the search endpoint with one symbol as the minimal authenticated call. One key per installation is HiThink's own model — every surface shares it — and per-desk keys would multiply what the operator pastes for no isolation gain, since reads are not desk-scoped facts.

`ponytail:` no rate-limit accounting per key; the passthrough's spacing (HT-4) is the whole throttle until a `4001` shows up in an attended bundle.

**Contract:** root [SPEC §4.4](../../SPEC.md#44-configuration-scopes); this feature's [SPEC](SPEC.md) §1.

### HT-2 — The `CN` leg polls HiThink's snapshot, batched, under R1's cadence and book

**Decision:** Catalog entries with `market = CN` are polled by the node's one out-of-tree `DataClient`, whose `CN` poll task reads `a_share_feed` at the top of every cycle: HiThink's batched snapshot whenever it is `HITHINK`, the Yahoo chart client exactly as R1 ships it otherwise. A switch takes effect on the next cycle with no node restart, the observation's `provider` field naming which provider produced it and the sequence continuing. `US` and `HK` entries keep the Yahoo client unchanged. Each catalog entry gains `hithink_symbol` beside `yahoo_symbol` — the `CN` entries carry their `thscode` (`600519.SH`, `000001.SZ`): the mapping from the Nautilus venue is fixed — `XSHG → SH`, `XSHE → SZ` — and asserted by `catalog::entries_valid`. One poll cycle is one request, `GET /api/a-share/prices/snapshot?thscodes=<every CN entry due>`, on R1's two-tier cadence (30 s idle, 10 s while an order or position is open, once at subscription whatever the phase). Because the batched reply's `timestamp` is documented `null`, source time is absent on `hithink` observations — `source_time_ns` is `null`, `age_ms` counts from receipt — and an item whose `(last_price, volume, turnover)` triple is unchanged since the last accepted observation replaces nothing. Prices are canonical decimal text at the instrument's precision, as today. Retry follows HiThink's contract: `4001` (rate limit) up to **3 attempts with exponential backoff** starting at 500 ms; `5xxx` and transport errors the same bound; `1xxx` and `2xxx` never retried. Exhaustion or any other failure leaves the last observation standing and marks health `DEGRADED`. A key rejected mid-run (`2003`) sets the row `UNAVAILABLE` and leaves `CN` instruments `DEGRADED` with the last HiThink observation standing; the daemon never flips the feed to Yahoo on its own, because that would be the silent provider substitution root §12.2 forbids — the operator does, through the toggle. Without a key the leg is simply Yahoo, and nothing about R1's behavior changes. The book stays synthesized: HiThink's snapshot carries no bid or ask either (`book_synthesized: true`, per D76).

**Rationale:** The user's call: everything A-share moves to HiThink. The toggle with Yahoo as its off state is the user's call on 2026-09-08: HiThink is an upgrade to the A-share leg, never a dependency of it, so a desk without a key loses nothing R1 gave it. Batching is the reason to move the feed rather than only add research: fifteen catalog entries will grow, and HiThink documents that per-symbol loops are the wrong shape while Yahoo needs one request per symbol. The `null` timestamp is a documented property of batch mode, so the honest contract exposes its absence rather than inventing a source time from receipt. The retry counts and the "never retry `1xxx`/`2xxx`" rule are HiThink's own error-code table, not a spike guess.

`ponytail:` change-detection on the price triple is the ceiling for "did the market move"; the per-symbol paged mode does carry a timestamp and is the upgrade if change detection ever misses a tick that matters.

`ponytail:` one poll task for the whole `CN` leg rather than R1's task per instrument, because one HiThink cycle is one request for all of them — so the two-tier cadence collapses to "the leg is exposed when any `CN` instrument is", and a Yahoo `CN` cycle polls the five entries in sequence instead of concurrently. The upgrade path is a per-instrument tier map narrowing the batch, if the `CN` catalog grows past a handful.

**Contract:** root [SPEC §12.2](../../SPEC.md#122-shared-reads-and-isolated-books); this feature's [SPEC](SPEC.md) §2.

### HT-3 — The A-share calendar is HiThink's trading-days list, refreshed once per Shanghai day, weekday rule as the fallback

**Decision:** While `a_share_feed` is `HITHINK`, the `CN` phase is `OPEN` inside R1's Shanghai sessions **and** on a date present in HiThink's `GET /api/a-share/calendar/trading-days` list; otherwise `CLOSED`. The list is fetched on the first `CN` subscription and again after the first poll tick past 00:00 Asia/Shanghai, held in daemon memory, never persisted. If no list has ever been fetched, or the fetch fails, the weekday rule alone applies until the next refresh succeeds; while the feed is `YAHOO` no list is fetched and the weekday rule applies, as in R1. Every `CN` observation carries `calendar: "HITHINK" | "WEEKDAY"` naming which rule labeled it. `US` and `HK` stay weekday-only (per D78).

**Rationale:** D78 recorded the missing holiday calendar as a deliberate ceiling with "a maintained source" as the upgrade path; HiThink is that source for one of the three markets, and the endpoint's fixed one-year window always contains today. Falling back to the weekday rule keeps a provider outage from turning a trading day into a silent `CLOSED`, and naming the rule on the observation is the honesty rule from §12.2.

**Contract:** root [SPEC §12.2](../../SPEC.md#122-shared-reads-and-isolated-books); this feature's [SPEC](SPEC.md) §3.

### HT-4 — Research is one allowlisted passthrough on `marketrig`, envelope verbatim, large bodies to a file

**Decision:** `GET /research/hithink/{path}?<query>` proxies one request to `https://fuyao.aicubes.cn/api/{path}` with the key attached and the query string forwarded verbatim, for `path` on a compiled-in allowlist of HiThink's documented endpoint paths (59 at design time, generated from the vendored capability map and checked against it). The upstream body is returned unchanged with status `200` whenever the upstream answered with a JSON envelope, whatever its `code` — the envelope is the contract the agent reads — and MarketRig's own envelope only for its own refusals: `RESEARCH_UNCONFIGURED`, `RESEARCH_PATH_UNKNOWN`, `RESEARCH_UNREACHABLE` (after HT-2's retry bound on `4001`, `5xxx`, and transport errors), `RESEARCH_TOO_LARGE` above 8 MiB. Requests are serialized installation-wide with at least 200 ms between upstream calls. Reads are not desk-scoped, carry no attribution, append no event, and write no row. The CLI is `marketrig [--json] research hithink <path> [--param key=value]… [--out <file>]`: the body prints to standard output up to 256 KiB; above that, or with `--out`, it is written to the named file or to `hithink-<path-with-dashes>-<unix-seconds>.json` in the working directory and the command prints the path and byte count. Exit codes are the CLI's fixed set; an upstream envelope with a nonzero `code` is still exit `0`, because the daemon did not fail.

**Rationale:** The user chose a thin passthrough over typed commands: the daemon never computes on a research field, so typing 56 endpoints would be drift with no reader. The allowlist keeps the daemon's key from being pointed at an arbitrary upstream path; the spacing is HiThink's stated expectation ("control request rhythm, no burst concurrency"); the file spill is the same rule HiThink's own skill imposes on its agents, moved into the one tool they have. Returning the upstream envelope verbatim, including its errors, keeps the vendored contract docs true without a translation layer; D4's "research through `marketrig`" is satisfied and D9's "informational, never a writer of trading state" is structural, since the route is `GET`-only.

`ponytail:` one global spacing gate and a fixed size ceiling; per-key budgets or streaming to disk arrive when a bundle shows the ceiling reached.

**Contract:** root [SPEC §13.2](../../SPEC.md#132-cli-continuity-plane); this feature's [SPEC](SPEC.md) §4.

### HT-5 — The upstream skill is vendored at a pinned commit and rewritten by a committed script into a `marketrig`-routed form

**Decision:** `vendor/hithink-finance/` holds `skills/hithink-finance/` from `HiThink-Tech/Financial-API` at one pinned commit, unmodified, with its license. `scripts/hithink-skill.mjs` produces `seed/skills/hithink-finance/` from it, committed, and CI checks the diff like `openapi.json`: it keeps `SKILL.md` and `references/api/**`, drops `references/{cli,mcp,python-sdk}.md` and their directories, replaces the routing, credential, installation, self-update, CLI-linkage, and failure-routing sections of `SKILL.md` with one English MarketRig-authored preamble — the only path is `marketrig research hithink <path> [--param k=v]`, the daemon holds the key, there is nothing to install, configure, or update — and rewrites every `curl 'https://fuyao.aicubes.cn/api/<path>?<q>' -H 'X-api-key: …'` example in the reference pages into the equivalent `marketrig research hithink <path> --param …` line by pattern. The data-contract prose stays as upstream wrote it, in Chinese. The result is seeded into every new desk's OpenViking user as skill `hithink-finance` beside `desk-improvement` and projected read-only (per D83); desks created earlier are never rewritten (per D20). Re-vendoring is a pin bump plus re-running the script.

**Rationale:** The user chose vendoring with edits over an English rewrite: the reference tree is the endpoint contract, and maintaining a second copy by hand is the drift the passthrough was chosen to avoid. The sections cut are exactly the ones that contradict MarketRig's contract — four surfaces, a key on the agent's side, installs into the agent's skills directory, a network self-update — and cutting them by script rather than by hand is what makes the next upstream bump cheap. Byte-identical under both locales (root §4.5) is a locale-invariance rule and holds: the seeded file is one file whatever the desktop locale.

`ponytail:` the rewrite is pattern-based and asserted by `skill::rewritten_examples_route_through_marketrig`; a curl form the pattern misses stays as upstream wrote it and the check reports the count.

**Contract:** root [SPEC §16](../../SPEC.md#16-memory-and-skills); this feature's [SPEC](SPEC.md) §5.

### HT-6 — A loopback HiThink stand-in in the gate; the real service in one attended scenario

**Decision:** The acceptance crate's stand-in HTTP server gains HiThink routes — search, snapshot, trading-days, one research path, and a scripted `4001` burst and a dark window — and the gate sets `MARKETRIG_TEST_HITHINK_URL` to it; a key of any value validates against the stand-in. Scenarios H1–H4 follow O10 (this feature's SPEC §6.2). The experiment gains E7: attended, real key, real HiThink, one cell per platform and runtime, agent-owned steps ending inconclusive rather than failed.

**Rationale:** The user chose the stand-in. It is the shape R1 gave Yahoo and D83 gave OpenViking, and it is what lets H2 script a non-trading weekday and H3 script a rate-limit burst deterministically.

**Contract:** root [SPEC §17](../../SPEC.md#17-verification-and-acceptance); this feature's [SPEC](SPEC.md) §6.
