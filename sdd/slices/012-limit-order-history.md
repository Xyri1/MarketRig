# Slice 012 — Limit-order history replays

**Status:** Active.

Corrects R1 SPEC §5 (durable schema, capture) and §10.2's G14 under D38 and R1-5. No new decision: the sandbox stays the only source of trading facts, and MarketRig still invents no event.

**Outcome.** `GET /desks/{desk_id}/history/orders` lists every order the desk captured, whatever path the venue took to fill it. Market orders are unchanged, row for row.

**Cause.** Found by E6 on 2026-09-08 (`target/acceptance/experiment-e6-claude-1788841651`): the desk's limit orders were missing from the history and the daemon logged `an order could not be replayed: Invalid order state transition`. Their stored chain was `OrderInitialized, OrderFilled`, which `OrderAny::from_events` refuses.

The daemon stored exactly what it received; NautilusTrader never published the rest. `nautilus-sandbox =0.62.0`'s execution client installs an event handler on its matching engine (`execution.rs`, `set_event_handler` at `nautilus-execution/matching_engine/mod.rs:244–252`), so both dispatch order events through the runner channel instead of straight to the execution engine, and one submit's events are all drained after `submit_order` has returned. By then a limit order that was marketable on arrival has taken `process_limit_order`'s taker branch (`matching_engine/mod.rs:3303–3319`), which accepts the order — applying `OrderAccepted` to its own copy — and `replace_order`s that copy into the node's cache before filling it. The drained `OrderSubmitted` and `OrderAccepted` are then refused as invalid state transitions (`engine/mod.rs:3231–3262`), so neither is applied and neither is published: only `OrderInitialized` and `OrderFilled` ever reach `events.order.*`. A limit order that rests takes the passive branch, which never replaces the cached order, so its full chain is published — which is why G14's resting order and every market order were fine. MarketRig's submit path is `nautilus-trading`'s own `Strategy::submit_order`, line for line (cache the order, publish `OrderInitialized`, send `SubmitOrder`), so nothing on the MarketRig side provokes it.

**Fix.** One change, in `crates/marketrigd/src/trade.rs`'s `capture_order`: the chain MarketRig stores is the node's *order* — the event list NautilusTrader keeps on it — not the stream that woke the handler. Each captured event appends whichever of the order's own events are not yet stored, in one unit with the fill rows and the book snapshot as before. The tail is chosen by NautilusTrader's own `event_id`, read back out of the stored payloads, never by position: the stored rows need not be a prefix of the order's chain — a database written before this rule is not one — and the same identity gate is what makes a second `fills` row for one trade id impossible. When the node holds no such order, the received event alone is stored, exactly as before. Every payload is still NautilusTrader's own, verbatim (per D38); nothing is synthesized, and no migration is needed because the payload already carries the id. A marketable limit order's chain is therefore `OrderInitialized, OrderAccepted, OrderFilled`, which replays.

**Exit checks.**

- Module: `trade::limit_order_history_replays` — a marketable limit buy and a resting one on a scripted feed; asserts the stored chain of the filled order and that `history_orders` lists both, newest first. Fails before the fix (the filled order is dropped), passes after.
- Module: `trade::capture_repairs_a_chain_stored_without_its_acceptance` — a chain rewound to the old two-row shape, then a cancel: exactly four events, one `fills` row, and a replay that lists the order. Fails under positional selection (two fills), passes under identity.
- Gate: G14 gains a marketable limit buy that partially fills, is cancelled, stores its `OrderAccepted`, is listed by `GET /desks/{desk_id}/history/orders`, and leaves no `could not be replayed` line in the log root. Its closing `g14-flat-aapl` sell returns the desk to flat so G17's book assertions are untouched, and adds one AAPL `position_cycles` row and its `EVALUATION` prompt to the R1 desk (`beta`), which now closes three cycles rather than two. No new G number.
- Static: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test -p marketrigd`, `cargo test -p marketrig-acceptance --test gate`.
